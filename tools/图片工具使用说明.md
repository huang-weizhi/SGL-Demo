# make_picture_bin.py 使用说明

这个工具做两件事：
1. 把多张图片文件（**.bin / .ebm 都可以**）**合并成一个** merged.bin（用于烧录到外部 Flash）
2. 自动生成每张图的 **Flash 地址表**（粘贴到 Inf_lcd_picture.h 里用）

**通常情况下你什么都不用填** —— 工具会自动扫描文件夹、自动识别每张图的尺寸
（优先从**同名的原始图片** .png/.bmp/.jpg 读取，其次看文件名里的 `36x36` 字样），
识别成功就直接输出结果。

---

## 前提准备

- 电脑装好 Python（3.x），命令行输入 `python --version` 能显示版本号即可
- 每张图片有取模输出文件（.bin 或 .ebm，RGB565、大端、按行扫描）
- **强烈建议把取模前的原始图片（.png/.bmp/.jpg）和取模文件放同一文件夹、同名**
  （例如 `电池图标.png` + `电池图标.ebm`）——工具靠它自动读尺寸

---

## 使用步骤（最简流程）

### 第 1 步：把文件放进一个文件夹

```
D:\my_pictures\
    alarm.ebm
    电池图标.ebm
    电池图标.png        ← 有它才能自动识别尺寸
    温度10.ebm
    温度10.png
```

注意：同一张图如果 .bin 和 .ebm 都在，工具只保留 .ebm（自动跳过 .bin 并提示）。

### 第 2 步：运行脚本（不带参数）

打开命令行（Win+R 输入 cmd 回车）：

```
进入目录：
cd /d D:\my_pictures
(cd /d "D:\Work Area\Code For WorkBench\FW_CZ01\tools\test")
运行脚本：
python ...\tools\make_picture_bin.py
或者直接运行：
python "D:\Work Area\Code For WorkBench\FW_CZ01\tools\make_picture_bin.py"
```

（`...\tools\` 换成脚本实际所在路径）

**如果所有图片尺寸都识别成功**，直接生成结果：

```
ok        电池图标.ebm    36x36   (from 电池图标.png)
ok        温度10.ebm      48x40   (from 温度10.png)

merged.bin  : merged.bin (xxxx bytes total)
table       : picture_table.txt
```

结束！跳到"第 3 步使用输出"。

**如果有图片识别不了尺寸**（没有同名原始图、文件名里也没 WxH 字样、
字节数又开不出完全平方数），工具会生成 `pictures.txt` 清单，
把识别出来的都填好，没识别的留 `? ?`，你只需把剩下几个补上，然后：

```
python ...\tools\make_picture_bin.py pictures.txt
```

### 第 3 步：使用输出

| 输出文件 | 干什么用 |
|---|---|
| `merged.bin` | 用 sscom 走烧写流程（发 `D1 AA AA AA AA FC` → 发送此文件 → 等 3 秒）烧到 Flash **地址 0** |
| `picture_table.txt` | 用记事本打开，**全选复制**，粘贴到 `Inf_lcd_picture.h` 的 `lcd_picture_table[]` 里，替换旧内容 |

重新编译烧录固件，代码里显示图片（序号 = 按名称排序的顺序）：

```c
lcd_show_picture(65, 105, 0, spiflash_read);   /* 显示 0 号图 */
```

## 尺寸自动识别的三条规则（按优先级）

1. **同名原始图片**：`xxx.ebm` 找 `xxx.png` / `xxx.bmp` / `xxx.jpg`，读图片头里的尺寸（最可靠）
2. **文件名里的 WxH 字样**：如 `电池图标 36x36.ebm` 直接取 36×36
3. **完全平方兜底**：字节数÷2 正好是某数的平方（如 1296=36×36），按正方形猜
   （会标注 `guessed square, PLEASE VERIFY`，建议核对）

另外每张图都会做**尺寸校验**：文件字节数 ≠ 宽×高×2 时报 MISMATCH 并拒绝打包，
防止错图混入。

---

## 常见报错

| 报错信息 | 原因和解决 |
|---|---|
| `MISMATCH: xxx is ... bytes, but WxH needs ...` | 识别到的尺寸和文件大小对不上（多半是原始图片和取模文件不是同一次导出），修正后重跑 |
| `unknown size: xxx` | 三条识别规则都没命中 → 用生成的 pictures.txt 手动填宽高 |
| `width/height not filled in yet (? ?)` | pictures.txt 还有 `? ?` 没填 |
| `missing file: ...` | 清单里的文件名和实际对不上（文件被改名/移动，重跑扫描） |
| `'python' 不是内部或外部命令` | 电脑没装 Python 或没加入 PATH，重装勾选 "Add Python to PATH" |

---

## 注意事项

1. **图片加了或删了 → 直接重跑一次脚本**就行（清单会重新生成，之前填的会丢；
   图片多且只是小改动时可手动编辑已有的 pictures.txt 再打包）
2. **merged.bin 每次都是整包烧录**（从地址 0 开始覆盖写入），不是增量更新
3. **图片序号 = 按名称排序的顺序**，代码里 `lcd_show_picture` 第 3 个参数就是它；
   同名 .bin/.ebm 并存时以 .ebm 为准
4. 若显示颜色不对（红蓝反），是取模软件输出的 RGB 顺序问题，和本脚本无关
5. 命令行窗口里中文显示乱码不影响功能，以文件内容为准（记事本打开正常）
